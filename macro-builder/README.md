# Макроконструктор — автоматизация браузера

Расширение для Chrome/Edge (Manifest V3), которое позволяет собирать из готовых
шагов («перейти по URL», «клик», «ввести текст», «извлечь таблицу», «цикл»,
«условие», «свой JS-код») макросы для автоматизации действий почти на любом
сайте — в том числе внутри `<iframe>` — и запускать их вручную, по расписанию
или автоматически при открытии нужного URL.

## Установка

1. Откройте `chrome://extensions` (или `edge://extensions`).
2. Включите «Режим разработчика» (переключатель в правом верхнем углу).
3. Нажмите «Загрузить распакованное расширение» и выберите папку `macro-builder`.
4. Иконка расширения появится на панели инструментов.

Если вкладка с нужным сайтом уже была открыта **до** установки/перезагрузки
расширения — обновите её один раз (F5), иначе скрипт-исполнитель там ещё не
подгружен.

## Быстрый старт

1. Иконка расширения, затем «Конструктор». Новый макрос создаётся из шаблона («Пустой макрос», «Обзвон по
   столбцу Excel», «Проверка строк таблицы на сайте») или загружается из файла.
2. Окно конструктора разделено на три зоны:
   - **слева** — список макросов, «Новый макрос», «Отчёты», «Конфиг»;
   - **в центре — «Структура»**: дерево шагов макроса. Каждая строка — номер, название шага и краткое описание
     («Ввести текст  #fio-input ← ${fio}»). Вложенные шаги условий и циклов видны всегда. «Не заполнено» в
     строке означает, что в шаге не хватает данных; счётчик «Замечаний» вверху ведёт к первому такому шагу;
   - **справа — свойства** выбранной строки: поля шага, разделённые на блоки («Элемент на странице»,
     «Что ввести» и т. д.), редкие настройки — в «Дополнительно». Кнопки «Проверить шаг», «Вверх», «Вниз»,
     «Копировать», «Удалить» — в шапке панели. Строка «Настройки макроса» открывает параметры запуска,
     автозапуск и «Запускать в новой вкладке».
3. Шаг добавляется кнопкой «Добавить шаг» (палитра с поиском по названию). Стрелки вверх/вниз по дереву
   переключают выбранный шаг с клавиатуры.
4. «Рабочая вкладка» вверху — вкладка сайта, с которой работают кнопки справа от полей селектора:
   - **«Указать на странице»** — кликните нужный элемент на сайте, селектор (и iframe) подставятся сами; пока вы
     водите курсором, элемент под ним обводится красной рамкой с названием (`input#q`, `button.dots "Действия"`);
   - **«Показать»** — подсвечивает красным все найденные элементы по текущему селектору (с номером и названием)
     и показывает на странице, сколько их нашлось; Esc убирает подсветку.
   - В шагах «Ввести текст» и «Очистить поле» кнопка называется **«Указать поле на странице»**: она выбирает именно
     поле ввода. Если кликнуть по обёртке, подписи или иконке (например, по `p-calendar` в Angular/PrimeNG или
     по `label`), выберется настоящий `input`/`textarea`/`contenteditable` внутри или рядом; клик по обычному тексту
     не засчитывается, а на странице появляется подсказка «Здесь нет поля ввода». «Показать» для этих шагов помечает
     найденное не-поле как `[НЕ ПОЛЕ ВВОДА]`. Сами шаги тоже ищут настоящее поле внутри найденной обёртки
     (в том числе в открытом shadow DOM); если однозначного поля нет, ошибка подскажет выбрать само поле.
   - Селекторы строятся устойчивыми: без служебных классов `ng-*`/`ng-tns-*`, с учётом `id` вида `formly_46_…`
     (номер отбрасывается) и атрибутов `data-testid`, `name`, `formcontrolname`, `aria-label`, `placeholder`.
   - Страница сайта подключается расширением при открытии: после обновления расширения обновите вкладку сайта (F5).
   - У шага «Ввести текст» есть галочка «убрать фокус с поля» — для полей, которые проверяют значение при потере
     фокуса (календари и маски).
   - «Записать действия» превращает ваши клики и ввод текста в шаги; «Проверить шаг» выполняет один шаг.
5. Значение, которое вводит макрос, **выбирается из списка**: столбцы загруженной таблицы («ФИО (fio)»),
   текущая запись цикла (для списка из одного столбца), переменные, служебные значения — либо «Свой текст». Так работают «Ввести текст», поле
   «С текстом» области поиска, значения в условиях и «Задать переменную». Список показывается только когда в
   макросе есть таблица или переменные; в остальных полях (например, «Открыть страницу») обычное поле ввода.
   Значения внутри шаблона отчёта вставляются списком «Вставить значение» под текстом отчёта.
6. «Проверить шаг» выполняет один шаг на рабочей вкладке; значения таблицы (`${fio}` и т. п.) при этом берутся
   из **первой записи** загруженной таблицы (какие именно, видно в журнале). Если шаг использует столбец
   таблицы вне цикла «Для каждой записи», строка структуры помечена «Нет данных» и в свойствах написано, что
   делать: кнопка **«В цикл»** вверху панели помещает этот шаг и все шаги ниже в новый цикл по таблице
   («Вынести» возвращает шаг из цикла или условия наружу); при запуске незаданная переменная, пустая ячейка для «Ввести текст» или «целая строка» вместо
   столбца дают понятную ошибку, а не тихий пустой ввод. Длинные числа из Excel (телефон, ИНН) читаются
   полностью, а не как `8,9E+11`.
7. «Запустить»: если у макроса есть параметры или цикл, откроется окно запуска — значения параметров,
   «В рабочей вкладке / В новой вкладке» и **пробный прогон** («только первые N записей»). Внизу — панель хода
   выполнения: полоса прогресса по записям и журнал (важное; «Подробно» — все шаги).
8. Макросы сохраняются автоматически. Из popup расширения макросы запускаются кнопкой «Запустить».
9. Пояснения к элементам — во всплывающих подсказках (наведите курсор).

Интерфейс только светлый (системная тёмная тема на него не влияет), без эмодзи и иконок.
Готовые примеры — в `examples/` (`autodozvon.json`, `excel-obzvon.json`, `proverka-strok.json`); они же доступны
как шаблоны нового макроса.

## Типы шагов

| Шаг | Что делает |
|---|---|
| Перейти по URL | `chrome.tabs.update` на целевой вкладке, ждёт полной загрузки |
| Клик по элементу | ждёт элемент (CSS/текст/XPath, опционально — внутри конкретного iframe и/или внутри нужной строки таблицы), скроллит к нему и кликает (шлёт pointerdown/mousedown/…/click, поэтому открывает и меню «три точки») |
| Очистить поле | стирает весь текст в поле ввода / textarea / contenteditable (React и Vue получают события input и change); есть и галочка «очистить поле перед вводом» в шаге «Ввести текст» |
| Навести курсор | pointerover/mouseover/mouseenter — для меню, которые раскрываются по наведению |
| Ввести текст | фокусирует поле, опционально очищает, вписывает значение (корректно работает и с React/Vue-полями), может нажать Enter |
| Пауза (мс) | просто ждёт указанное время |
| Дождаться элемента | опрашивает DOM, пока элемент не появится или не истечёт таймаут |
| Загрузить данные из Excel/CSV | читает один столбец (список) или несколько столбцов (таблица построчно) файла `.xlsx`/`.xls`/`.xlsm`/`.csv`; умеет пропускать строки по длине значения — см. «Данные из Excel и CSV» |
| Задать переменную | записывает значение (с `${подстановкой}`) или увеличивает счётчик |
| Дописать в MD-отчёт | добавляет блок Markdown в отчёт; файл сохраняется в «Загрузки» в конце запуска — см. «Отчёты» |
| Перейти в новую вкладку / Закрыть вкладку и вернуться назад | работа с вкладкой, открытой страницей (или ссылкой элемента) — см. «Новые вкладки» |
| Извлечь данные | берёт text/value/html/атрибут у одного элемента или у всех совпадений сразу — и сохраняет в переменную |
| Извлечь таблицу | по селектору строк собирает массив объектов (по одной колонке-селектору на поле) — для парсинга списков/таблиц |
| Экспорт в CSV | сохраняет переменную-массив (например, результат «Извлечь таблицу») в CSV-файл через `chrome.downloads` |
| Условие | «если … то … иначе»: одна или несколько проверок (элемент есть; текст элемента сравнить со значением из таблицы; сравнить две переменные), объединённых по И/ИЛИ — см. «Условия» |
| Повторить N раз | вложенные шаги выполняются N раз, счётчик доступен как `${имя_переменной}` |
| Для каждого значения из списка | перебирает значения списка **или строки таблицы** (поля строки становятся переменными); умеет ограничить число записей, помнить прогресс и не падать на ошибке в одной строке — см. «Цикл по таблице» |
| Следующая строка / Выйти из цикла / Завершить макрос | управление ходом: пропустить остаток записи, прервать цикл, закончить макрос (не ошибка) |
| Свой JS-код | выполняется в собственном JS-контексте страницы (`world: "MAIN"`); доступны `vars`, `helpers.$`/`helpers.$$`, `helpers.sleep(ms)`, а также переменные/функции самой страницы; возвращённое значение можно сохранить в переменную |
| Нажать клавишу | шлёт keydown/keyup активному элементу |
| Прокрутка страницы | до конца страницы или до конкретного элемента |

У шагов, работающих со страницей, есть настройка повтора при ошибке:
количество дополнительных попыток, задержка между ними и что делать, если
так и не получилось — остановить макрос или пропустить шаг и продолжить.

### Работа внутри `<iframe>`

У шагов с селектором (клик, ввод, ожидание, извлечение, условие, свой JS-код)
есть поле «Фрейм: URL содержит» — если оставить пустым, шаг работает с
основной страницей; если указать подстроку URL фрейма (например,
`checkout` или `payments.example.com`), шаг найдёт элемент именно в этом
`<iframe>`. Пипетка и запись действий подставляют это поле автоматически,
если клик произошёл внутри iframe.

## Данные из Excel и CSV

Шаг «Загрузить данные из Excel/CSV» превращает файл в данные для макроса. Выберите файл
(`.xlsx`, `.xls`, `.xlsm`, `.csv`, `.tsv`; CSV в UTF-8 и в windows-1251, разделитель
определяется сам), затем лист, и один из двух режимов:

- **Один столбец → список значений.** Подходит для обзвона по номерам телефонов и т. п.
  Список отдаётся шагу «Для каждого значения из списка».
- **Несколько столбцов → таблица построчно.** Отметьте нужные столбцы и задайте каждому
  имя переменной (по умолчанию — транслитерация заголовка: «ФИО» → `fio`, «Номер полиса» →
  `nomer_polisa`). В цикле по такой таблице поля строки доступны как `${fio}`, `${polis}` и т. д.,
  а ещё `${_row}` — настоящий номер строки в Excel, `${_index}`/`${_total}` — позиция в цикле.

Значения берутся в том виде, как они показаны в Excel (форматированный текст), поэтому номера
полисов и телефоны с ведущими нулями или пробелами не портятся. Можно обрезать пробелы, пропускать
пустые ячейки/строки и оставлять только уникальные значения.

### Пропуск строк по длине значения

Под настройками столбцов — «+ Правило пропуска»: **пропускать, если длина значения столбца**
*не равна / больше / меньше / равна / ≥ / ≤* **N**. Длину можно считать по всем символам, «только цифры»
(для телефонов: `+7 (905) 419-40-15` → 11) или «символы без пробелов». Правил может быть несколько
(строка пропускается, если сработало любое). В сводке шага видно, сколько записей пропущено.
Те же операции есть в условиях («длина равна / НЕ равна / больше / меньше…»), чтобы пропускать
запись прямо внутри цикла (`Условие` → `Следующая строка`).

**Как это работает и ограничения**

- Расширение не читает файл во время запуска (у него нет доступа к файловой системе), поэтому в
  макросе сохраняется **снимок данных** на момент выбора файла. Благодаря этому макрос работает и
  при запуске из попапа, и по расписанию/URL.
- Файл изменился — откройте макрос в конструкторе и выберите его заново: лист подставится по имени,
  столбцы — по заголовку (даже если порядок столбцов поменялся), правила пропуска сохранятся.
- Лимиты: 50 000 значений для одного столбца и 10 000 строк для таблицы (данные лежат в
  `chrome.storage.local`); при превышении шаг предупреждает.
- Если в шаге нет данных (или всё отсеяно правилами), макрос остановится с понятной ошибкой.

Готовые примеры: `examples/excel-obzvon.json` (обзвон по столбцу) и `examples/proverka-strok.json`
(проверка строк таблицы на сайте, см. ниже).

## Проверка строк таблицы на сайте (пример сценария)

Задача: для каждой строки таблицы открыть страницу, вписать ФИО, нажать «Искать», подождать,
сравнить результат поиска с данными строки, открыть «три точки» → «Посмотреть данные полиса»,
в новой вкладке считать данные и записать результат в MD-файл.

1. «Загрузить данные из Excel/CSV» → режим «таблица построчно», столбцы `fio`, `polis`,
   правило пропуска (например, номер полиса не равен 18 символам).
2. «Для каждого значения из списка» → переменная `rows`; «Если в записи ошибка» →
   «пропустить запись и идти дальше»; прогресс запоминается сам, при необходимости его можно сбросить в панели цикла.
3. Внутри цикла: «Перейти по URL» → «Ввести текст» `${fio}` → «Клик» «Искать» → «Пауза» 2000 мс.
4. «Условие»: проверка «текст элемента» `строка результата` **содержит все слова** `${fio}`.
   - **То:** «Клик» по кнопке «⋮» с областью поиска «внутри `tr`, где есть текст `${fio}`» →
     «Клик» по тексту «Посмотреть данные полиса» → «Перейти в новую вкладку» → «Извлечь данные»
     (поля карточки в переменные) → «Закрыть вкладку и вернуться назад» → «Дописать в MD-отчёт».
   - **Иначе:** «Дописать в MD-отчёт» «не найдено».
5. Блок «При ошибке» цикла: «Дописать в MD-отчёт» с `${_error}`.

Селекторы в `examples/proverka-strok.json` — заглушки: подставьте свои кнопкой «Указать на странице».

## Условия

Шаг «Условие» состоит из списка проверок и логики: **все выполнены (И)** или **хотя бы одна (ИЛИ)**.
Каждую проверку можно инвертировать («НЕ»), а ещё у неё есть «Ждать выполнения до, мс» — проверка
опрашивается, пока не станет истинной (например, пока не появятся результаты поиска).

| Проверка | Что делает |
|---|---|
| Элемент есть на странице | как раньше: найден ли элемент (по умолчанию учитываются только видимые) |
| Текст элемента сравнить со значением | читает текст/`value`/`href` найденных элементов и сравнивает с `${значением}`; проверять «хотя бы один / первый / все» элементы |
| Сравнить два значения / переменные | левое и правое значения с `${подстановкой}` |

Операции сравнения: равно, содержит, **содержит все слова** (ФИО: порядок слов не важен,
инициал «Ю.» совпадает с «Юрий»), начинается с, регулярное выражение, пусто / не пусто, числа
(`=`, `>`, `≥`, `<`, `≤` — понимает «16 639,00 ₽»), длина значения. По умолчанию регистр, «е/ё» и
лишние пробелы игнорируются (переключается галочками у проверки).

Важно: **пустое ожидаемое значение никогда не «содержится» в тексте** — строка с незаполненным ФИО
не совпадёт с любым результатом поиска. В журнале запуска для каждой проверки видно, что реально
нашли на странице.

Старые макросы с условием «элемент найден / не найден» продолжают работать без изменений.

## Область поиска: внутри нужной строки

У шагов с селектором (клик, наведение, ввод, ожидание, извлечение, проверки, переход по href) есть
поля «Искать внутри контейнера» (CSS строки, например `tr` или `.result-row`) и «…у которого в
тексте есть» (например `${fio}`). Тогда элемент ищется только внутри строки с нужным текстом — так
«три точки» нажимаются именно в строке с этим клиентом, а не в первой попавшейся. Без селектора
шаг возвращает саму найденную строку (можно извлечь её текст целиком). XPath внутри контейнера
относительный (`.//button`). Подбирайте контейнер по строке: слишком общий (`div` вокруг всей
таблицы) найдёт кнопку первой строки.

## Новые вкладки

- **Перейти в новую вкладку** — после клика, который открывает вкладку (`target=_blank` или
  `window.open`), следующий шаг выполняется уже в ней; «Закрыть вкладку и вернуться назад» возвращает
  в прежнюю. Вкладки, которые макрос открыл внутри записи цикла и не закрыл, закрываются
  автоматически в конце записи — в том числе после ошибки.
- Если сайт открывает вкладку через `window.open`, Chrome может заблокировать её как всплывающее окно
  (автоматический клик — не «настоящее» действие пользователя): разрешите всплывающие окна для
  этого сайта (значок в адресной строке) **или** выберите вариант «Открыть ссылку (href) найденного
  элемента» — тогда вкладку открывает расширение и блокировка не применяется.

## Цикл по таблице

У шага «Для каждого значения из списка»:

- **Обработать не больше N записей** — для пробного прогона на живом сайте (0 — все);
- **Запоминать обработанные записи и продолжать с места остановки** (включено у нового цикла) — если запуск
  прервали (ошибка, «Остановить», закрыли браузер, вы делаете таблицу порциями с лимитом), следующий запуск
  с этой же таблицей пропустит уже обработанные записи. Запись узнаётся по содержимому (значения столбцов),
  а не по номеру строки, поэтому прогресс не теряется, если таблицу поправили: удалили или добавили строки,
  поменяли порядок, строки сместились. Изменённая запись считается новой. Отчёты MD при продолжении
  дописываются к накопленным, а не начинаются заново. Когда таблица пройдена целиком, прогресс очищается сам.
  - в панели цикла («Продолжение работы») видно, сколько записей обработано и с какой пойдёт работа
    («Обработано 120 из 500 · следующая запись - 121»), и есть кнопка **«Сбросить прогресс»**;
  - в окне запуска, если есть что продолжать, выбирается **«Продолжить с записи N»** или **«Начать сначала»**;
    пробный прогон прогресс не трогает;
  - в popup у макроса с сохранённым прогрессом показано «Обработано N из M» и есть «Сбросить прогресс»
    (запуск из popup продолжает автоматически);
- **Если в записи ошибка** — остановить макрос (как раньше) или пропустить запись и идти дальше;
  тогда выполняются шаги блока «При ошибке» (доступна `${_error}`).

Внутри цикла: «Следующая строка» пропускает остаток записи, «Выйти из цикла» прекращает цикл.

## Отчёты (MD)

Шаг «Дописать в MD-отчёт» накапливает Markdown в буфере с заданным именем файла. Файл записывается
в папку **«Загрузки»** в конце запуска (в том числе при ошибке или остановке; при повторном запуске
файл перезаписывается, длинный отчёт режется на части `…-1.md`, `…-2.md`). Буфер дублируется в
хранилище расширения: кнопка «Отчёты» слева внизу — накопленное можно скачать или
удалить — на случай, если запуск оборвался. «Начинать отчёт заново при каждом запуске» выключается,
если нужно дописывать к уже накопленному. Имя файла можно задать с подпапкой (`Проверки/отчёт.md`).

## Конфиг: сохранить и загрузить

Макросы хранятся в браузере (`chrome.storage.local`) и пропадают при переустановке расширения или
на другом компьютере. Кнопка «Конфиг» слева внизу:

- **Сохранить конфиг в файл** — все макросы в один `.json`. По умолчанию **данные таблиц в файл не
  попадают** (это выгрузки с персональными данными клиентов) — остаются только настройки: лист,
  столбцы, имена переменных, правила пропуска. Галочка «с данными таблиц» включает и сами данные
  (тогда файл нельзя пересылать).
- **Загрузить конфиг** — макросы с тем же id заменяются, новые добавляются; если в файле нет
  данных таблицы, а в браузере они уже есть, они сохраняются. Файл Excel в шаге выбирается заново,
  столбцы подхватятся по заголовкам.
- «Экспортировать в JSON» / «Импортировать из JSON» одного макроса — в меню «Действия» справа вверху (импорт создаёт копию).

## Триггеры запуска

Помимо ручного запуска, у макроса можно настроить один или несколько
триггеров (раздел «Триггеры запуска» в конструкторе):

- **Через интервал** — запускать каждые N минут (`chrome.alarms`);
- **Каждый день в** — запускать раз в сутки в указанное время;
- **При открытии URL** — запускать автоматически, как только в любой вкладке
  открывается страница, URL которой подходит под шаблон (можно использовать
  `*` как маску, например `https://example.com/orders*`).

При автозапуске значения входных параметров берутся из их полей «по
умолчанию» (заполните их в разделе «Входные параметры», если планируете
использовать триггеры). Есть защита от зацикливания: пока автозапуск того
же макроса на той же вкладке ещё выполняется, повторно он не стартует — но
если сам макрос содержит шаг «Перейти по URL» на адрес, который тоже
подходит под его собственный триггер «При открытии URL», логическая петля
всё равно возможна, так что таких сочетаний стоит избегать.

## Переменные

Любое поле `url`/`value`/`селектор` понимает подстановку `${имя}`. Источники
переменных:

- **входные параметры** макроса — их значения запрашиваются перед запуском
  (можно сделать многострочными — тогда это готовый список для шага «Для
  каждого значения из списка»);
- значения, сохранённые шагами **«Извлечь данные»**, **«Извлечь таблицу»** и
  **«Свой JS-код»** (поле «Сохранить в переменную»);
- переменная-счётчик циклов (`i`, `item` и т.п. — имя настраивается);
- поля столбцов таблицы в цикле по строкам (`${fio}`…), `${_row}`, `${_index}`, `${_total}`; `${_error}` — в блоке «При ошибке»;
- встроенные `${_now}` (`2026-09-30 14:05:09`), `${_date}`, `${_time}`;
- шагом «Задать переменную».

Над списком шагов в конструкторе — панель «Переменные»: клик по имени вставляет `${имя}` в последнее выбранное поле.

## Известные ограничения

- Работает только с обычными `http(s)` страницами — `chrome://` и страницы
  веб-магазина недоступны для автоматизации (ограничение самого браузера).
- «Свой JS-код» выполняется в собственном JS-контексте страницы, поэтому
  подчиняется её реальной Content-Security-Policy: на страницах, которые
  сами явно запрещают `unsafe-eval` (некоторые банковские/платёжные сайты),
  этот шаг тоже будет заблокирован — так же, как заблокирован был бы ручной
  `eval` в консоли разработчика на такой странице.
- Запись действий отслеживает клики и `change` на полях ввода/селектах;
  drag&drop, canvas-интерфейсы и т.п. записью не ловятся — такие шаги проще
  добавить вручную через «Свой JS-код».
- Всплывающие окна: см. «Новые вкладки» (разрешить для сайта или открывать по href).
- Сайты с защитой от автоматизации, которые различают «настоящий» клик от
  синтетического (`event.isTrusted`), текущим способом (DOM-события) не
  обманываются — для них нужен другой уровень ввода (`chrome.debugger`/CDP),
  которого в расширении нет.

## Разработка

- Чтение Excel/CSV: `excel-import.js` (чистые функции), библиотека SheetJS лежит в
  `vendor/` (лицензия — `vendor/LICENSE-xlsx.txt`).
- Логика условий, сравнения, конфига и отчётов: `logic.js` (чистые функции).
- Интерфейс: `builder.js` (структура, панель свойств, запуск, панель выполнения), `ui/editors.js` (редакторы шагов),
  `ui/data-step.js` (мастер таблицы), `ui/meta.js` (иконки, описания шагов, проверка заполненности —
  чистые функции), `ui/dom.js` (элементы, окна, меню), `styles.css` (единая светлая тема).
- Юнит-тесты (Node 18+): `node --test macro-builder/tests/*.test.mjs` (среди них проверка, что в исходниках нет эмодзи и тёмной темы).
- Сквозные тесты в настоящем Chromium с загруженным расширением и «сайтом-имитацией» (поиск, «три точки»,
  карточка в новой вкладке): `tests/e2e/` (нужен `playwright`):
  `NODE_PATH=$(npm root -g) node macro-builder/tests/e2e/backend.e2e.mjs` и `…/ui.e2e.mjs`.

## Безопасность

Шаг «Свой JS-код» выполняет произвольный код в контексте открытой страницы —
у него те же возможности, что и у кода, который сама страница могла бы
выполнить через `eval` в консоли разработчика. Импортируйте JSON-файлы
макросов только из источников, которым доверяете — в них может быть
закодирован именно такой шаг.
