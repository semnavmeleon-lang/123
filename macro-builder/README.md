# Макроконструктор — автоматизация браузера

Расширение для Chrome/Edge (Manifest V3), которое позволяет собирать из готовых
шагов («перейти по URL», «клик», «ввести текст», «извлечь таблицу», «цикл»,
«условие», «свой JS-код») макросы для автоматизации действий почти на любом
сайте — в том числе внутри `<iframe>` — и запускать их вручную, по расписанию
или автоматически при открытии нужного URL.

## Установка

1. Откройте `chrome://extensions` (или `edge://extensions`).
2. Включите «Режим разработчика» (переключатель в правом верхнем углу).
3. Нажмите «Загрузить распакованное расширение» и выберите папку `macro-builder`.
4. Иконка расширения появится на панели инструментов.

Если вкладка с нужным сайтом уже была открыта **до** установки/перезагрузки
расширения — обновите её один раз (F5), иначе скрипт-исполнитель там ещё не
подгружен.

## Быстрый старт

1. Кликните по иконке расширения → «Конструктор» (или сразу «+ Новый макрос»).
2. Слева выберите вкладку-цель в разделе «Целевая вкладка» — это та вкладка,
   на которой будет работать кнопка «🎯 Выбрать элемент» и запись действий,
   и на ней же будет выполняться макрос (если не включено «Запускать в новой
   вкладке»).
3. Добавляйте шаги кнопкой «+ Добавить шаг» внизу списка, либо нажмите
   «● Записать шаги» и просто покликайте/поводите по нужному сайту — клики и
   заполнение полей автоматически превратятся в шаги макроса (переходы между
   страницами и клики внутри `<iframe>` во время записи тоже фиксируются).
4. Для шагов с селектором есть кнопка «🎯» — кликните её и затем кликните
   нужный элемент на целевой вкладке (в т.ч. внутри iframe), селектор и
   (если нужно) фрейм подставятся автоматически.
5. У каждого шага есть кнопка «▶» — выполняет только этот шаг на целевой
   вкладке, без запуска всего макроса. Удобно при отладке.
6. «▶ Запустить» — выполнит макрос по порядку, с журналом в самом низу.
   «Остановить» прерывает выполнение перед следующим шагом.
7. Макросы сохраняются автоматически (в `chrome.storage.local`). Из попапа
   расширения можно быстро запускать уже готовые макросы без захода в
   конструктор.

Готовый пример — `examples/autodozvon.json`: обобщает уже существующие в
репозитории HTML-страницы «Автодозвон» (звонок через один номер) в макрос,
который проходит по **списку** номеров через IP-телефон Yealink. Импортируйте
его кнопкой «Импорт JSON» в конструкторе, чтобы увидеть пример использования
циклов, `customJs` и подстановки `${переменных}`.

## Типы шагов

| Шаг | Что делает |
|---|---|
| Перейти по URL | `chrome.tabs.update` на целевой вкладке, ждёт полной загрузки |
| Клик по элементу | ждёт элемент (CSS/текст/XPath, опционально — внутри конкретного iframe), скроллит к нему и кликает |
| Ввести текст | фокусирует поле, опционально очищает, вписывает значение (корректно работает и с React/Vue-полями), может нажать Enter |
| Пауза (мс) | просто ждёт указанное время |
| Дождаться элемента | опрашивает DOM, пока элемент не появится или не истечёт таймаут |
| Извлечь данные | берёт text/value/html/атрибут у одного элемента или у всех совпадений сразу — и сохраняет в переменную |
| Извлечь таблицу | по селектору строк собирает массив объектов (по одной колонке-селектору на поле) — для парсинга списков/таблиц |
| Экспорт в CSV | сохраняет переменную-массив (например, результат «Извлечь таблицу») в CSV-файл через `chrome.downloads` |
| Условие | проверяет, есть ли элемент на странице, и выполняет одну из двух вложенных веток шагов |
| Повторить N раз | вложенные шаги выполняются N раз, счётчик доступен как `${имя_переменной}` |
| Для каждого значения из списка | перебирает значения из входного параметра или ранее извлечённой переменной (список, либо строка, разделённая переводами строк/запятыми) |
| Свой JS-код | выполняется в собственном JS-контексте страницы (`world: "MAIN"`); доступны `vars`, `helpers.$`/`helpers.$$`, `helpers.sleep(ms)`, а также переменные/функции самой страницы; возвращённое значение можно сохранить в переменную |
| Нажать клавишу | шлёт keydown/keyup активному элементу |
| Прокрутка страницы | до конца страницы или до конкретного элемента |

У любого шага (кроме «Экспорт в CSV») есть настройка повтора при ошибке:
количество дополнительных попыток, задержка между ними и что делать, если
так и не получилось — остановить макрос или пропустить шаг и продолжить.

### Работа внутри `<iframe>`

У шагов с селектором (клик, ввод, ожидание, извлечение, условие, свой JS-код)
есть поле «Фрейм: URL содержит» — если оставить пустым, шаг работает с
основной страницей; если указать подстроку URL фрейма (например,
`checkout` или `payments.example.com`), шаг найдёт элемент именно в этом
`<iframe>`. Пипетка и запись действий подставляют это поле автоматически,
если клик произошёл внутри iframe.

## Триггеры запуска

Помимо ручного запуска, у макроса можно настроить один или несколько
триггеров (раздел «Триггеры запуска» в конструкторе):

- **Через интервал** — запускать каждые N минут (`chrome.alarms`);
- **Каждый день в** — запускать раз в сутки в указанное время;
- **При открытии URL** — запускать автоматически, как только в любой вкладке
  открывается страница, URL которой подходит под шаблон (можно использовать
  `*` как маску, например `https://example.com/orders*`).

При автозапуске значения входных параметров берутся из их полей «по
умолчанию» (заполните их в разделе «Входные параметры», если планируете
использовать триггеры). Есть защита от зацикливания: пока автозапуск того
же макроса на той же вкладке ещё выполняется, повторно он не стартует — но
если сам макрос содержит шаг «Перейти по URL» на адрес, который тоже
подходит под его собственный триггер «При открытии URL», логическая петля
всё равно возможна, так что таких сочетаний стоит избегать.

## Переменные

Любое поле `url`/`value`/`селектор` понимает подстановку `${имя}`. Источники
переменных:

- **входные параметры** макроса — их значения запрашиваются перед запуском
  (можно сделать многострочными — тогда это готовый список для шага «Для
  каждого значения из списка»);
- значения, сохранённые шагами **«Извлечь данные»**, **«Извлечь таблицу»** и
  **«Свой JS-код»** (поле «Сохранить в переменную»);
- переменная-счётчик циклов (`i`, `item` и т.п. — имя настраивается).

## Известные ограничения

- Работает только с обычными `http(s)` страницами — `chrome://` и страницы
  веб-магазина недоступны для автоматизации (ограничение самого браузера).
- «Свой JS-код» выполняется в собственном JS-контексте страницы, поэтому
  подчиняется её реальной Content-Security-Policy: на страницах, которые
  сами явно запрещают `unsafe-eval` (некоторые банковские/платёжные сайты),
  этот шаг тоже будет заблокирован — так же, как заблокирован был бы ручной
  `eval` в консоли разработчика на такой странице.
- Запись действий отслеживает клики и `change` на полях ввода/селектах;
  drag&drop, canvas-интерфейсы и т.п. записью не ловятся — такие шаги проще
  добавить вручную через «Свой JS-код».
- Сайты с защитой от автоматизации, которые различают «настоящий» клик от
  синтетического (`event.isTrusted`), текущим способом (DOM-события) не
  обманываются — для них нужен другой уровень ввода (`chrome.debugger`/CDP),
  которого в расширении нет.

## Безопасность

Шаг «Свой JS-код» выполняет произвольный код в контексте открытой страницы —
у него те же возможности, что и у кода, который сама страница могла бы
выполнить через `eval` в консоли разработчика. Импортируйте JSON-файлы
макросов только из источников, которым доверяете — в них может быть
закодирован именно такой шаг.
