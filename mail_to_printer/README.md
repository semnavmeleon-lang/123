# mail_to_printer

Скрипт берёт **отправленные** письма, превращает каждое в PDF (шапка От/Кому/Дата/Тема + текст/HTML +
встроенные картинки + список вложений) и отправляет его на «виртуальный принтер» и/или кладёт в папку.

Письма можно брать двумя способами (`[mail] backend` в `config.ini`):

| backend | Когда подходит |
|---|---|
| `outlook` | **Корпоративный Outlook / Microsoft 365 на Windows.** Читает «Отправленные» прямо из установленного классического Outlook: ни пароля, ни IMAP, ни прав администратора. |
| `imap` | Gmail, Яндекс, Mail.ru, свой Exchange/почтовый сервер, где IMAP включён и работает вход по паролю. |

Каждое письмо обрабатывается один раз: скрипт запоминает, что уже сделано, в `state.json`.
Письма в ящике не меняются.

## Установка

```bash
pip install -r requirements.txt
cp config.example.ini config.ini   # заполните backend / printer / output_dir (+ host, user для imap)
```

PDF делает браузер Chromium. Варианты:
* Windows: в `config.ini` поставьте `browser_path = msedge` — используется уже установленный Edge, ничего скачивать не надо.
* иначе: `playwright install chromium` (один раз, ~150 МБ).

Для `imap`: пароль задавайте переменной окружения (`export MAIL_PASSWORD=...`, PowerShell: `$env:MAIL_PASSWORD='...'`).
Для Gmail / Яндекс / Mail.ru нужен **пароль приложения** и включённый IMAP.

## Корпоративный Outlook (backend = outlook)

Условия:
* **Windows** и **классический** Outlook (тот, что «Файл / Главная / Вставка…» в приложении на компьютере).
  «Новый Outlook» (переключатель *New Outlook* в углу) и веб-версия COM не поддерживают — нужно переключиться на классический.
* Скрипт запускается **под тем же пользователем Windows**, что и Outlook, в его сеансе (не как служба).
  Если Outlook закрыт, он запустится в фоне сам.
* Берётся папка «Отправленные» основного ящика профиля Outlook.
* Если Outlook на каждое обращение спрашивает «Программа пытается получить доступ к адресам…», это политика антивируса/Outlook — обратитесь к ИТ.

```ini
[mail]
backend = outlook
[output]
printer = имя_виртуального_принтера
output_dir = pdf_out
browser_path = msedge
```

Почему не IMAP: в Microsoft 365 администратор обычно отключает вход по логину/паролю. Для OAuth нужна регистрация
приложения в Azure AD с согласием администратора — режим `outlook` этого не требует.

## Установка

```bash
pip install -r requirements.txt
playwright install chromium        # один раз, ~150 МБ. Либо укажите browser_path на свой Chrome/Edge
cp config.example.ini config.ini   # заполните host / user / printer / output_dir
export MAIL_PASSWORD='пароль-приложения'   # Windows PowerShell: $env:MAIL_PASSWORD='...'
```

## Запуск

```bash
python mail_to_printer.py                    # один проход (для cron / Планировщика заданий)
python mail_to_printer.py --watch            # работать постоянно, проверка раз в poll_seconds
python mail_to_printer.py --all              # первый запуск: обработать ВСЕ старые письма
python mail_to_printer.py --since 2026-01-01 # первый запуск: старые письма начиная с даты
```

**Важно:** при первом запуске (нет `state.json`) существующие письма по умолчанию **пропускаются** —
чтобы случайно не отправить тысячи писем на печать. Нужны и старые — `--all` / `--since`.

## Какой «принтер» указать

| Система | Что поставить | `printer =` |
|---|---|---|
| Linux | `sudo apt install printer-driver-cups-pdf` — PDF падают в `~/PDF` | имя из `lpstat -p` (обычно `PDF` / `Cups-PDF`) |
| macOS | «PDF Services» / любой виртуальный PDF-принтер; или CUPS-PDF | имя из `lpstat -p` |
| Windows | PDFCreator или Bullzip PDF Printer в режиме автосохранения **и** SumatraPDF для тихой печати (или свой `print_cmd`) | имя принтера из «Принтеры и сканеры» |

Встроенный «Microsoft Print to PDF» на каждый файл спрашивает имя — для автоматики не подходит.

Если вам нужны просто PDF-файлы, принтер вообще не нужен: оставьте `printer =` пустым и задайте `output_dir`.
Если принтер настоящий, а не виртуальный, каждое письмо будет реально печататься.

Своя команда печати (`print_cmd`) поддерживает подстановки `{printer}`, `{file}`, `{title}` и запускается без shell.

## Автозапуск

* Linux: `crontab -e` → `*/5 * * * * cd /путь/к/mail_to_printer && MAIL_PASSWORD=... python3 mail_to_printer.py`
  (или `--watch` под systemd).
* Windows: Планировщик заданий → «Создать задачу» → действие `python mail_to_printer.py` каждые 5 минут.

## Как это устроено / ограничения

* Письмо с ошибкой (принтер недоступен, битое письмо) пробуется до 3 раз, потом пропускается. В режиме `outlook` порядок сохраняется:
  пока письмо не прошло (или не исчерпало 3 попытки), более новые ждут.
* Картинки из интернета по умолчанию не загружаются (`load_remote_images = no`); скрипты в письмах не выполняются.
* Вложения в PDF не включаются — только их список.
* IMAP: если папка «Отправленные» называется нестандартно — задайте `sent_folder` вручную.

## Тесты

```bash
pip install pypdf
python -m unittest -v        # BROWSER_PATH=/путь/к/chrome, если не ставили браузер Playwright
```

## Что проверено, а что нет

Автотесты (23 шт.) проверяют разбор писем, PDF (с кириллицей и картинками), печать, повторы, состояние и IMAP на настоящем `imaplib`.
Режим `outlook` протестирован на заглушках COM-объектов, повторяющих API Outlook, — **но не на живом Outlook**:
первый запуск лучше сделать на нескольких письмах (`--since` с сегодняшней датой) и посмотреть результат в `output_dir`.
