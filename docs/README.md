# Надстройка Outlook «Сохранить письмо»

Веб-надстройка (Office.js task pane) для Outlook: добавляет кнопку **«Сохранить письмо»**
на ленту при просмотре письма. По нажатию письмо (тема, отправитель, получатели, тело
и обычные вложения) скачивается на компьютер в виде файла `.eml` через папку «Загрузки» браузера.

Работает в новом Outlook, Outlook в браузере (OWA), классическом Outlook для Windows и Outlook для Mac.

Файлы надстройки (`manifest.xml`, `taskpane.html`, `taskpane.js`, иконки) раздаются
**локально, с вашего же компьютера** через маленький Python-сервер — никакого внешнего
хостинга не нужно. Но Outlook в любом случае требует HTTPS (даже для localhost), поэтому
один раз нужно сделать самоподписанный сертификат и добавить его в доверенные.

Понадобится: Python (любой современный, 3.8+) и `openssl` (обычно уже есть, если установлен
Git for Windows).

---

## Шаг 0. Скачать/обновить файлы проекта

Если проект уже лежит у вас в папке (клонирован через git) — просто откройте терминал
**в этой папке** и подтяните последние изменения:
```
git pull
```
(это команда `git`, а не отдельная программа — набирайте именно `git pull`, не `bash pull`).

Если проекта на компьютере ещё нет — склонируйте репозиторий (или скачайте ZIP с GitHub
и распакуйте) так, чтобы внутри папки лежали `docs/` и `tools/`.

Дальше все команды выполняются **из корня этой папки** (там, где видны папки `docs` и `tools`).

## Шаг 1. Сгенерировать сертификат для localhost

Нужны два файла: `tools/localhost-cert.pem` и `tools/localhost-key.pem`. Сделать их можно
любым из двух способов — выберите тот, что у вас заработает.

### Способ А (рекомендуется): openssl через готовый конфиг

В репозитории уже есть файл `tools/openssl-san.cnf` — он описывает сертификат для `localhost`.
Откройте терминал **Git Bash** (не PowerShell — там своего `openssl` нет; в VS Code переключить
терминал можно стрелкой рядом с `+` в панели терминала, либо просто откройте Git Bash отдельным
окном через меню Пуск и перейдите `cd` в папку проекта) и выполните:
```bash
openssl req -x509 -newkey rsa:2048 -keyout tools/localhost-key.pem -out tools/localhost-cert.pem -days 3650 -nodes -config tools/openssl-san.cnf
```
На запрос passphrase ничего вводить не нужно — флаг `-nodes` его отключает.

Если `openssl` в Git Bash не находится вообще — значит на компьютере не установлен
Git for Windows. Поставьте его с https://git-scm.com/download/win (обычный установщик,
права администратора не обязательны — есть вариант «только для себя»), откройте **новое**
окно терминала после установки и повторите команду.

### Способ Б: Python + cryptography

```
pip install cryptography
python tools/generate_cert.py
```
Если `pip install` зависает или падает по таймауту — почти наверняка корпоративный
прокси/firewall блокирует `pypi.org`/`files.pythonhosted.org`. В этом случае проще
использовать способ А. Если всё же нужен именно pip — узнайте у ИТ адрес прокси и
выполните `pip install --proxy http://ваш-прокси:порт cryptography`.

## Шаг 2. Добавить сертификат в доверенные

Без этого шага Outlook и браузер будут ругаться на сертификат.

### Без прав администратора (обычный случай на рабочем компьютере)

Ставим сертификат не для всего компьютера, а только для вашего пользователя — админские
права для этого не нужны. Обычный (не «от имени администратора») PowerShell:
```powershell
Import-Certificate -FilePath tools\localhost-cert.pem -CertStoreLocation Cert:\CurrentUser\Root
```
Появится диалог с предупреждением безопасности — нажмите **Да**. Этого достаточно: и
Outlook, и браузер проверяют личное хранилище сертификатов пользователя точно так же, как
хранилище всего компьютера.

Если PowerShell вообще не даёт выполнить команду — то же самое через интерфейс: дважды
кликните `tools\localhost-cert.pem` → **Установить сертификат** → выберите **Текущий
пользователь** (не «Локальный компьютер») → «Поместить все сертификаты в следующее
хранилище» → Обзор → **Доверенные корневые центры сертификации** → ОК → Далее → Готово →
подтвердите предупреждение безопасности («Да»).

### Если есть права администратора

Можно поставить сразу для всех пользователей компьютера, в PowerShell **от имени
администратора**:
```powershell
Import-Certificate -FilePath tools\localhost-cert.pem -CertStoreLocation Cert:\LocalMachine\Root
```
Это не обязательно — вариант выше (CurrentUser) полностью достаточен для того, чтобы
надстройка заработала у вас.

## Шаг 3. Запустить локальный сервер

```
python tools/serve.py
```
Он поднимет `https://localhost:3000/` и будет отдавать `manifest.xml`, `taskpane.html`
и иконки из папки `docs/`. Для этого шага `cryptography` не нужна в любом случае — сам
сервер написан на чистом Python (`http.server` + `ssl`), библиотека нужна была только
для способа Б на шаге 1.

**Оставьте это окно терминала открытым**, пока пользуетесь надстройкой — если сервер
остановить, кнопка на ленте Outlook останется, но панель перестанет открываться. Проще
всего запускать сервер при каждом включении компьютера и не закрывать окно.

Проверить, что всё работает: откройте в браузере `https://localhost:3000/manifest.xml` —
должен показаться XML без ошибок сертификата.

## Шаг 4. Установить надстройку в Outlook

### Новый Outlook / Outlook в браузере (OWA)
1. Откройте любое письмо → **⋯ (Ещё действия) → Получить надстройки** (Get Add-ins).
2. Слева: **«Мои надстройки» → «Добавить пользовательскую надстройку» → «Добавить из
   URL-адреса»**.
3. Вставьте ссылку на манифест: `https://localhost:3000/manifest.xml`.
4. Подтвердите установку.

### Классический Outlook (Windows) / Mac
1. **Файл → Управление надстройками** (или лента **Главная → Получить надстройки**).
2. **Мои надстройки → Добавить пользовательскую надстройку → Добавить из файла/URL**.
3. Укажите ту же ссылку на манифест, либо скачайте `manifest.xml` и добавьте из файла.

После установки откройте любое письмо на чтение — на ленте появится кнопка
**«Сохранить письмо»**. Нажатие открывает панель задач с кнопкой сохранения — жмите
«Сохранить письмо», файл `.eml` уйдёт в папку «Загрузки».

## Что сохраняется

- Тема, отправитель, получатели (To/Cc), дата — как заголовки письма.
- Тело письма в формате HTML.
- Обычные вложения (файлы), закодированные в письмо как часть `.eml`.
- «Облачные» вложения (ссылки на OneDrive/SharePoint) не скачиваются как файлы — только
  сама ссылка, если она есть в письме; такие файлы нужно скачивать вручную по ссылке.

Файл `.eml` — стандартный формат письма, открывается двойным кликом в Outlook, Почте
Windows, Thunderbird и большинстве других почтовых клиентов.

## Если что-то не так

- **`openssl: req: Extra option: "addext"`** — старая версия openssl, не понимает флаг
  `-addext`. Используйте способ А с готовым конфигом `tools/openssl-san.cnf` (см. выше) —
  он работает на любой версии.
- **`bash: pull: No such file or directory`** — опечатка, нужно `git pull` (одна команда,
  без `bash` перед ней).
- **`openssl` не найден в PowerShell** — так и должно быть, у PowerShell нет своего
  `openssl`. Используйте терминал **Git Bash**.
- **Ошибка сертификата в браузере/Outlook** — сертификат не добавлен в «Доверенные
  корневые центры сертификации» (шаг 2), либо сервер (шаг 3) запущен с другим
  сертификатом, чем импортирован. Удалите `tools/localhost-*.pem`, сгенерируйте заново
  (шаг 1) и повторите импорт (шаг 2).
- **Панель не открывается / «не удалось подключиться»** — не запущен
  `python tools/serve.py` (шаг 3).
- **Порт 3000 занят** — освободите его или поменяйте `PORT` в `tools/serve.py` и во всех
  ссылках `https://localhost:3000/...` внутри `docs/manifest.xml`.
- **Outlook пишет «Файл манифеста не соответствует определению схемы»** — если вы
  редактировали `manifest.xml` вручную, проверьте порядок и названия тегов по
  официальным примерам Microsoft; XML должен быть валиден (`python -c "import
  xml.dom.minidom as m; m.parse('docs/manifest.xml')"` покажет синтаксические ошибки,
  но не проверяет саму схему Office).
